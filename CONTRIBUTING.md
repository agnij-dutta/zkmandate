# Contributing

Thanks for looking. Bug reports, reviews of the circuit and the registry, and small
focused PRs are all welcome. For anything that could be a soundness or fund-loss bug, use
private reporting instead (see [SECURITY.md](SECURITY.md)).

## Setup

| tool | version | install |
|---|---|---|
| nargo | `1.0.0-beta.19` | `noirup -v 1.0.0-beta.19` |
| bb | `4.0.0-nightly.20260120` | `bbup -v 4.0.0-nightly.20260120` |
| Foundry | 1.5.x | `foundryup` |
| Node | 22 (>= 20) | |

The bb and nargo versions must match the pinned `@aztec/bb.js` and `@noir-lang/noir_js`
in `sdk/package.json`, or proofs and verification keys will not line up.

```bash
git clone --recurse-submodules https://github.com/agnij-dutta/zkmandate
cd zkmandate
(cd sdk && npm ci)
./scripts/build.sh
./scripts/test-all.sh
```

`scripts/*.sh` look for `~/.nargo/bin/nargo` and `~/.bb/bb`; override with `NARGO=` and
`BB=` (see `.env.example`).

## Layout

```
circuits/src/main.nr                Noir circuit and its nargo tests
contracts/src/PrivateMandateRegistry.sol  escrow + state chain + proof check
contracts/src/HonkVerifier.sol       generated by bb, do not edit by hand
contracts/test/                      forge tests; fixtures/payments.json holds real proofs
sdk/src/                             hash.ts (Poseidon2 + tags), merkle.ts (allowlist), index.ts (prover API)
sdk/scripts/                         demo, fixtures, bench, local anvil helpers
scripts/                             build.sh, test-all.sh, bench-native.sh
```

## Tests, lint, format

```bash
./scripts/test-all.sh                       # nargo test + forge test + SDK typecheck + SDK tests
(cd circuits && nargo fmt --check)
(cd contracts && forge fmt --check)
(cd sdk && npm run lint)                    # ESLint + Prettier check; `npm run format` fixes
```

CI (`.github/workflows/ci.yml`) runs all of these and also fails if the committed verifier
or SDK circuit artifact is stale.

## Changing the circuit

The circuit, the verifier, the SDK and the proof fixtures move together:

1. Edit `circuits/src/main.nr` and add a nargo test for the new rule, including a
   `should_fail_with` test that shows the rule actually bites.
2. `./scripts/build.sh`: recompiles, writes the VK, regenerates `HonkVerifier.sol`,
   copies the stripped artifact into `sdk/circuit/`, runs `forge build`.
3. `(cd sdk && npm run fixtures)`: regenerates the real proofs the forge tests replay.
4. If you touched hashing, update `sdk/src/hash.ts` and the vectors in
   `sdk/test/sdk.test.ts` (print them with `nargo test --show-output test_vectors_for_sdk`).
5. If you touched public inputs, update their order in three places: `main`'s parameters,
   `PrivateMandateRegistry.pay`, and `ZkMandateProver.prove`. `test_PublicInputOrderMatchesCircuit`
   and the SDK "valid payment" test check it.

### Adding a mandate rule

A new rule (for example a per-payee cap or a not-before time) usually means: a new private
term inside `mandate_commitment` (with the SDK's `mandateHash` and `MandateTerms` updated
to match), an `assert` in `main` with a distinct message, a matching `MandateViolation`
reason in `sdk/src/index.ts`, and tests on all three layers. Keep every hash role on its
own domain tag.

## Commits and PRs

Small commits with plain messages ("Add per-payee cap to the circuit"). Fill in the PR
checklist. By contributing you agree your work is released under the MIT license.
